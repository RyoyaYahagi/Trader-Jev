# 米国株特徴量の時間整合性の修正

2026-10-13に、Jevへ渡す入力の品質を調査して修正しました。
対象は共通の `generate_quant_features` です。質問や信頼度基準は変更していません。

## 修正理由

従来の共通特徴量生成では、足の開始時刻がsnapshot以前なら、その足を使用していました。
例: 14:30:30のsnapshotに14:30開始の1分足を含めると、まだ終わっていない足の価格が
確定済みの値としてリターン、VWAP、ボラティリティへ入ります。
実験用質問2.1のrunnerには別途確定足フィルタがありましたが、既定の旧方式にはありません。

また、5分変化率は5本前、15分変化率は15本前との比較でした。
足が欠けたり重複すると、比較する時間幅がラベルと異なります。
以前の最後の足が古い場合も、その足から計算した変化率を現在の指標として返していました。

## 修正後

- 足は開始から1分経過し、snapshot以前に確定した場合だけ使用。
- 直近の確定1分足の時刻を基準に、1・5・15・60分前の時刻と比較。
  必要な両端がない場合はnull。途中の欠落だけを理由にリターンを拒否しない。
- 同一足の重複は一度だけ集計。矛盾する重複は入力順に依存せず除外。
- ボラティリティは連続する1分足の変化を集計。欠落をまたぐ変化は含めない。
- 計算不能な短期トレンド強度を `unavailable` に記録。

JPY予備資金、手数料、RiskEngine、仮想約定基準、質問セット、信頼度下限、
最大保有時間は変更していません。

## 保存データで確認した影響

10/9に固定した240ケースの元のfeature recordを、元SQLiteを読み取り専用で開いて再計算しました。
外部モデルの呼び出しは0件。将来の値動きや損益を入力へ加えていません。

| 比較対象 | 数値が変わったケース |
| --- | ---: |
| 元の旧方式の保存特徴量 | 238 / 240 |
| 改善版2.1の保存入力 | 0 / 240 |

旧方式では1分・5分変化率が236件、15分が225件、60分が195件で変わりました。
VWAPとの距離は238件、実現ボラティリティは221件、短期トレンド強度は225件で変わりました。
数値ではない `unavailable` の一覧の追加はこの件数に含めていません。

この比較は旧方式の入力への影響を示すものです。改善版2.1の取引損失の説明や、
利益・信頼度の改善の証明にはなりません。入力JSONが変わるケースの旧回答は、
修正後の質問への回答として使い回せません。

## 検証

未確定・未来・前日・時間外・欠落・古い足・重複を扱うテストを含め、全270テストを通過。
指定時間の両端がある場合は、途中が欠けても正しい変化率を返すことも確認しました。
Ruff lint、pyright、変更Pythonファイルの整形検査も通過しました。
全体の整形検査には既存6ファイルが未整形で残ります。今回の変更には含めていません。

監査結果と再計算スクリプトはローカルの
`data/validation/us-feature-time-integrity/` に保存し、Gitには含めません。
自動運用runtimeへの反映はこの修正作業では行っていません。
